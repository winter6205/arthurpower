# skill-authoring — Rationalization Table Reference

## Rationalization Table

| Excuse | Reality |
|--------|---------|
| "Description is obviously clear" | Clear to the author is not clear to other agents. Test with 20 trigger queries. |
| "It's just a reference skill" | Reference skills have retrieval gaps. Test that the agent finds the right section. |
| "Testing is overkill for a small skill" | Small untested skills grow into large untested skills. Test early. |
| "I'll add Rationalization Table later" | Later = never. Add it before the first commit. |
| "Description is too long already" | Long description is a routing failure. Move procedure and examples out of L1 into L2/L3; keep description trigger-only. |
| "Bar upgrade is bureaucracy" | Bar mismatch = silent quality drift. The validator catches it, the reviewer confirms it. |
| "200 char target is a soft guideline" | The 200-char lower target is review guidance, not a validator failure. Below-target descriptions are allowed only when routing evals prove coverage. |
| "Genericization is auto-enforced" | Auto-enforced by the validator. The skill must state the rule, and the validator is the executable source of truth for exact forbidden patterns. |
